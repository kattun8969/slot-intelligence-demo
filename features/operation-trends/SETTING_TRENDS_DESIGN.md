# 設定投入傾向：複数証拠・時間変化モデル（設計 v0.2）

## 目的
「過去に高設定だった可能性」と「次回の投入見込み」を分け、店舗×機種×日付×イベント単位で根拠を蓄積する。差枚プラスを高設定確定とみなさない。店舗や地域の差を優先し、全国共通の機種特性は弱い事前仮説に留める。

## 収集する証拠
- official_event_result: 取材主催者・店舗が公開する対象台・答え合わせ。公開時刻、開催日、対象範囲、後出し/事前告知の区別、URL、取得日、利用許諾を記録。取材側の「対象」は設定確定を意味しない。
- confirmed_setting: 設定確定演出等の一次報告。演出の意味・機種バージョン・撮影日・投稿者・画像権利を検証。本人の投稿でも未検証なら報告扱い。
- social_report: SNSの実戦報告、反例、引用・リポスト。引用投稿は同一原投稿を一件として重複排除し、投稿日時と実戦日を分離。人気や拡散数を独立した証拠件数に換算しない。
- public_machine_data: 差枚、G数、初当たり、設置台数。欠測と稼働不足を区別。
- store_event: 特定日、取材、リニューアル、増台、機種移動、地域イベント。
- machine_context: 導入日、稼働・人気、設置台数、バラエティ/主力区分、出玉分布、見せ台適性。

## 仮説の扱い
- バラエティは投入頻度が低い可能性、人気機種は高い可能性、荒い機種と安定機種では見せ台・利益管理の動機が違う可能性を特徴量にする。
- どの仮説も「店舗によって逆転し得る」と明記し、事前重みは低く設定する。
- 北斗転生、ゴッドイーター、SAO2の例は変化検出の検証ケースとし、実測なしに順位や投入率を確定しない。
- 過去90日と直近28日など複数窓を比較し、変化点・導入後経過・増減台を検出。期間は後から検証で調整する。
- 同一店舗のデータを優先し、地域の似た店舗はデータ不足時の補助とする。全国傾向の安易な転用を避ける。

## 評価の出力
- historical_evidence: 過去の確認・推定実績（根拠、標本数、対象日）
- prospective_signal: 将来の投入を示唆する方向性（上昇/横ばい/下降/判断不可）
- evidence_quality: 出典独立性、一次/二次、対象期間、サンプル、欠測、反例、権利確認
- confidence: 低/中/高。これは証拠の信頼度であり「設定6確率」ではない。
- explanations: 支持する根拠と反証をそれぞれ表示。
- provenance: URL、公開日、取得日、投稿/取材イベントID、ライセンス状態、原文の再利用可否。

## 実装上の境界
収集器はアダプタ方式とし、利用規約・robots・API規約・権利の確認前にスクレイピングを実行しない。SNS埋込も規約確認後に採用する。初期版では手動入力・許諾済みCSV/JSONのみ受け入れる。

既存の期待値エンジンには手を入れず、将来の接続は versioned JSON API を介する。高設定投入の傾向と遊技の期待収支は別の指標であり、足し合わせない。

## 検証
同一投稿のリポスト重複、後出し取材対象のリーク防止、未来データ混入防止、機種名の同一性、導入前日付、低稼働のバイアス、時間窓ごとの予測検証を必須とする。
