## 見本を使う際の限界
- ブラウザ「名前を付けて保存」で得られるHTMLは**WordPressのPHP、管理画面設定、REST API、投票/D1等のサーバー動作を含まない**。保存済みJavaScriptも本番同等の動作を保証しない。
- PDFはレイアウトの参考であり、正確なCSS幅・スマホ端末の操作検証ではない。320px/375pxの実画面チェックは②が本番で行う。
- 保存データにブラウザ拡張由来コード、管理者リンク、機密情報、権利上転載不可の資料がないか共有前に確認する。
- 著作物画像や有償資料をPublic GitHubへ複製しない。リコリコ固有の文章・数値・機種固有CSSは、そのまま他の機種へ流用しない。

## 正式な変更フロー
1. ②がリコリコ本番を改修・表示検証した場合、必要に応じ新たなHTML/関連ZIP/スマホPDFを作る。
2. プロジェクトソースに`v2`等で**旧版を残して**追加し、専用チャットで差分を整理。
3. 差分を「共通化する変更／機種固有変更」「デザイン／記事構成／期待値／PAPIMO／狙い目／示唆／スマホ」に分類。
4. 共通ルールへの反映案をIssueで③に提示し、承認された内容のみ制作基準に反映。②が必要に応じ他機種へ適用。
5. 本ファイルに版・変更の要旨・参照先・適用済みIssueを記録。**見本更新だけで全機種への自動変更はしない**。
