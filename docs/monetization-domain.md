# ④ 収益化・独自ドメイン準備

## 安全な初期状態
`monetization/config.json` は全体・広告・支援とも disabled。外部サービスURL未登録のため表示なし。既存の機種解析・計算・Pages設定には変更を加えない。

## 組み込み
現状は共通モジュールを追加した段階で、既存ページへの読み込みは未接続。ページの解析・期待値表の後ろに空のコンテナを配置し、CSSとJSを読み込んで `SlotMonetization.render(config, container, "machine", {adsDisabled:false})` を呼ぶ。トップは `"home"`。広告非表示は将来サーバーで検証した会員状態からのみ渡すこと（クライアント側の値は課金権限の証明にならない）。現行トップの CSP は外部スクリプトを許可していないため、読み込み統合時には安全な同一オリジンへの CSP 調整が必要。広告画像・リンクの送信先と外部サービスの利用規約を確認すること。

## 配置
期待値表・狙い目・設定別勝率・出玉性能の途中には置かず、主要コンテンツ終了後のみ。ページ別の配置指定は `placements` で保持。PR は必ず表示。広告案件は `affiliate.offers`、投げ銭は `support.services` で管理。個別 `enabled:true` と有効なURLが必要。

## GitHub Pages 独自ドメイン手順（未実施）
1. 希望ドメインを購入し所有権を確認する。
2. GitHub Settings > Pages の公開元（branch / Actions）を確認する。
3. サブドメイン（例 www）なら DNS CNAME を `kattun8969.github.io` に設定。apex なら GitHub Pages の公式 A/AAAA レコードを最新ドキュメントで確認して設定する。
4. GitHub Pages の Custom domain を設定し、DNS 検証後 Enforce HTTPS を有効化する。
5. `/slot-intelligence-demo/` 前提の絶対パス、相対画像パス、canonical、sitemap、OG URL、内部リンクを新URLに合わせて検証する。
6. Google Search Console に新ドメインのプロパティを追加し DNS 所有権確認、サイトマップを送信する。旧 github.io プロジェクトURLからの自動301リダイレクトを前提にしない。旧URLのアクセス・検索流入を監視する。
7. 本番ドメイン切替はユーザーの事前承認後に実施する。
