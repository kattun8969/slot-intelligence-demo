## ページの順序

1. ページ内ナビ → 中央の筐体画像 → 機種概要の表。
2. PAPIMO等のホール実績は期間・台数・全設定混合の別を明記。出玉分布は折りたたむ。設定別勝率とホール全体のプラス台率、AT/ST獲得枚数と差枚を区別する。
3. 期待値チェックは記事内で完結。条件とカウンターを明示し、金額は円で表示。補間と実測を区別し、範囲外は根拠がある場合のみ推定幅を出す。貸出・交換枚数と現金投資を指定した換算は参考表示。
4. 投票・実戦報告、個人の期待値記録は折りたたみ。公開集計と個人保存を分け、個人の共通記録には機種IDと略称を持たせ、テキストコピーに対応する。
5. 狙い目とやめ時。ゾーン、天井・短縮条件、ホールで拾える狙い目、条件別の期待値表、やめ時を順に記載。天井と狙い始めを別列にし、CZまで・ATまで・ゾーン終了までを混同しない。拾えそうな履歴と期待値の適用条件を照合し、金額の根拠があるものを円で表示する。
6. 示唆は実画面の画像と意味を並べる。アイキャッチは独立した見出しにする。画像の対応と掲載条件を確認し、利用できる場合はちょんぼりすたを優先。解析情報の外部出典は別タブで開く。

## 重要な示唆の制作ルール（①ライター）

遊技中に表示された画面を、読者がその場で照合できる一覧を作成する。

- 見出しは「ST終了画面」「CZ失敗後のカード」「ステージ切り替え時のアイキャッチ」など、出現場面を基準にする。用途が明確なときは「（設定判別）」「（天井短縮）」「（モード・設定）」などを添える。確認操作が必要なら冒頭に記載する。
- 通常・弱示唆も含め、出典で確認できるパターンを一覧化する。各項目には掲載できる実画面、キャラ・枠色・背景などの見分け方、示唆内容、意味が変わる条件を添える。画像が用意できない項目も識別情報と示唆内容は掲載できる形で提出する。
- 同じ見た目・出現条件に対して設定とモードなど複数の示唆がある場合は、同じ項目に併記する。「濃厚」「期待度アップ」などの強さは出典に合わせる。続行・やめ時に関わる場合は確認済みの適用条件と該当箇所への導線を添える。
- 320px・375px幅で画像・名前・意味を同じ項目内で読めるようにする。折りたたむ場合は「CZ失敗後のカードをすべて見る」のように対象をラベルに書く。
- 出典と確認日を添え、画像や解析が未確認の項目はIssueで管理する。完成した項目は先行公開できる形で提出する。

## 公開の確認

- スラッグは安定した英語表記。変更時はトップのリンクと旧URLの転送を確認。
- 期待値表は「ホールで拾える狙い目」の直下で折りたたむ。フォームと表は同じデータに基づく。更新前後で既存情報とユーザー機能の動作を確認。
- ①は出典・確認日・適用条件・数値の根拠を用意。②は実装、スマホ確認、本番確認。③は優先順位、依存関係、完了条件を管理。
- 優先順は筐体画像 → 添付データがある機種の期待値表 → PAPIMO → 狙い目。期待値表に時間がかかる場合はPAPIMOを先行。
- **旧GitHub Pagesへの更新・デプロイ・マージは禁止**。公開先はWordPress本番のみ。②Work編集者がWordPressで下書き・編集・公開し、本番URLで検証する。ブラウザー操作が必要な更新は認証済み環境を使い、認証情報をGitHubに保存しない。
- WordPressの既存実装にはリコリコ専用のページ条件があるため、複数機種へ接続する際は機種IDごとのデータ設定へ展開する。

## 作業順序・添付資料・Work利用枠（2026-11-22追加）

- ①は**オーナー提出済みの期待値表・画像を最優先の根拠**として、数値と条件・カウンター・終了地点・貸出交換条件を確認する。数値未確認時は捏造せず、完成した独立掲載可能な他項目を先に提出する。購入資料の原本・実質的複製はPublic GitHubへ置かない。
- **公開速度優先の並行調査**：オーナー提出資料の確認と同時に、メーカー公式・無料公開解析サイト・無料の期待値/狙い目情報・PAPIMO・SNS原投稿を収集する。無料で確認できた機種情報は出典URL、確認日、開始/終了条件、交換条件、推定・実測の別を揃え、独自編集した部分原稿として②へ先行提出する。無料公開であっても原表・画像の安易な転載は禁止。
- **異なる数値の扱い**：無料記事と提出資料で数値が違う場合は、対象カウンター（AT/CZ/ボーナス/周期）、設定変更・短縮条件、貸出/交換、現金/持ちメダル、やめ時・閉店減算、調査時点を比較し、整合しない値を混合しない。根拠不明の円額は創作せず、既存の他項目と確認済み情報を公開可能な形で進める。
- **停止回避と引き継ぎ**：保存ZIP展開や画像の閲覧に失敗しても同じエラーの反復で作業を止めず、ファイル名・失敗操作・必要な解決策をIssueに残し、③へ解決依頼する。①は確認済み原稿・WordPressコードを②編集待ちに登録。②は一括公開時に完成部分を採用し、未確認の期待値表は後日追記する。
- 示唆は設定判別用・期待値稼働用の双方の需要を考え、同じ出現画面に複数の意味がある場合は同じ項目で併記し、用途別に判別しやすくする。
- ページの要点は320px/375pxでも読めるようにし、期待値チェック、投票、示唆は機種ページ内で完結させる。既存内容を削らず、公開可能部分の先行公開を許す。
- ②Workは**毎時起動せず、手動・複数案件の一括編集**を原則とする。①③④は編集に必要な原稿・出典・実装手順をIssueに揃える。公開確認と公開判断は [publication-policy.md](publication-policy.md) に従う。
