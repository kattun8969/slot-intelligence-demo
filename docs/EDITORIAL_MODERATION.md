# 実戦報告と現場候補の採択フロー

## 収集
- 一般向け報告受付は休止中。GitHub Issue の投稿テンプレートは一時撤去した。ローカルの実戦メモは本人の端末内に留まる。将来はGitHubログイン不要の投稿窓口とスパム対策を検討する。
- X/解析サイトの公開投稿は URL、投稿日、機種型式、発言と根拠の区別を保持する。転載・リポスト・同じホールの同一台は重複カウントしない。
- 連絡先・ユーザーIDなどの個人情報や有料データをコピーしない。

## AIによる一次整理（自動公開しない）
- 機種型式、天井・周期・ゾーン、G数起点、交換率、設定変更状況、やめどき、根拠資料のURLを抽出。
- 解析確定事項・投稿者の推測・単発実戦結果を分離。矛盾、サンプル数、重複、投稿日時・適用条件の差を点検。
- 未検証の期待値額や空き台頻度・人気順位を作らない。利害関係のある投稿、ステマ、改ざん疑義は保留する。

## 公開審査
- 人が原典を見て採択/保留/却下する。採択した要約だけ `reviewed-field-reports.json` にコミットし、必ず出典と確認日を残す。
- 自動投稿・自動承認は禁止。将来AI解析を追加しても提案までに限定。
- 不適切な投稿の非表示・訂正・撤回、出典の削除に対応。公開後に新たな根拠が出た場合は履歴を残して再審査する。
- 『見つけやすい候補』は需要・設置台数・履歴分布を測定するまではランキングとせず「現場候補（検証中）」と表現する。

## 公開JSONフィールド
`schema:1`、`items` 内の各報告に `id,machine,title,summary,caution,source_url,reviewed_at,scope` が必要。数値がある場合はさらに交換率・起点・やめどきとデータの根拠を添える。
