# 機種別カウンター定義：登録・検証手順

`data/ev/counter-rules.json` は **確認済みルール0件** から開始する。サイト上の機種が存在することは、店舗データ提供元のカウンター仕様が確認できたことを意味しない。

`python -m scripts.ev_machine_rule_readiness` で、機種・型式・提供元・店舗ごとに、確認済み/審査中/却下/競合ルールを集計する。レポートは標準出力のみ。公開ページ・収支データ・ルールを変更しない。

## ルール登録前に必要な情報

- 提供元の識別子、店舗ID、機種ID、型式、表示ラベル、イベント名
- カウンターの意味（AT間/CZ間/周期/日別差枚/区間差枚など）と起点
- 定義の適用開始日・終了日、ルールID・版
- 根拠のHTTPS URL、取得日、確認者、利用許諾の別途確認
- `review_status` は確認前 `pending` とし、根拠を確認してから `verified` にする

**重要**: `mapping_ready` はデータの意味が一意に読めることだけを示す。実戦の開始条件・投資額・回収額・交換率・やめどきが揃わない限り、独自期待値は公開できない。`ev_publication_ready` は常にfalse。

## 次段階
許諾済みの実データが入手できたとき、ルールの重複検証→観測レコードの版固定→時系列監査を行う。出典が確認できない値は推測で埋めない。

## 適用日指定による判定

`python -m scripts.ev_machine_rule_readiness --as-of 2026-11-15` のように対象日を指定すると、その日に有効な確認済みルールだけを `mapping_ready` に数える。期限切れ・将来のルールは除外する。日付指定なしの場合は従来の**全履歴の登録状況**を表示し、`readiness_scope=all_historical_rules` と明示する。現時点の適用状況を調べるときは必ず日付を指定する。
