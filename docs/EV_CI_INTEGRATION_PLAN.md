# 独自期待値開発：自動テストとPR統合手順

## 専用CI
`.github/workflows/ev-research-tests.yml` は `scripts/ev_*.py`、`tests/test_ev_*.py`、`data/ev/**` などに変更があるPRで起動する。Python 3.12で構文チェック、ルールJSONの形式チェック、`python -m unittest discover -s tests -p 'test_ev_*.py' -v` を実行する。公開サイトのデプロイは行わない。

## 注意
- 本CIがmainに入る前に作られたPR #32/#33/#34/#37/#39/#40では、**CIが走っていないことはテスト合格を意味しない**。
- このPR単体では既存のEVモジュールがmainにまだ存在しないため、テスト0件のまま成功する可能性がある。**各PRの統合前に必ず該当するテストが検出・実行されたことを確認する**。
- Pythonの構文・単体テスト合格は実店舗データの正確性、公開期待値の根拠、利用規約への適合を保証しない。
- 公開サイト、機種ページ、公開期待値表を更新する作業は別チャット担当。

## PR統合前のチェックリスト
1. 対象PRの先頭SHA、mainの先頭SHA、変更ファイル、他PRとの競合を確認。
2. PR #32/#33/#34/#37/#39/#40をレビューし、各モジュールの単体テストを**実際に実行**する。
3. API契約の不一致を確認。特に、PR #33の正規化結果は台番号・タイムスタンプ・順序のアダプターが必要。PR #32の集計結果をPR #39へ渡す際はカウンター起点と出典種別が必要。
4. テスト数・失敗数を記録。0件実行は合格扱いにしない。
5. CI成功・競合なし・変更範囲を確認後に、明示的なマージ判断を行う。
6. 統合後に実データの欠損・重複・出典・許諾・状態判定を検証する。
